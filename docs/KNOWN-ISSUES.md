## K-003 · `config.php.example` named a retired mail host
**Severity:** medium · **Status:** fixed in the template on 2026-09-04. The live server value
is **UNVERIFIED**

`server/config.php.example` set both `$SMTP_HOST` and `$IMAP_HOST` to a host that was retired
in the July 2026 migration.

**Why it was worse than a stale string:** a retired host of that kind still resolves and still
answers on port 465, so a `config.php` copied from the template connects to a machine where
the mailboxes no longer exist. It fails as an authentication error at best, and silently at
worst. It never fails as "host not found", which is the failure people watch for.

**What was done:** both values are now `REPLACE_smtp_host` and `REPLACE_imap_host`, with a
comment stating that the real hostname is a hosting fact held in the operator's notes and not
in this repository, and warning about the silent-failure mode. A placeholder fails loudly on
connection, which is the behaviour wanted from a template.

**What is still open:** whether the **live** `config.php` on the server points at the retired
host. That cannot be checked from here. See `docs/DEPLOYMENT.md` section 5.

**Related, same change:** `DB_NAME`, `DB_USER` and `$SEED_ADMIN_EMAIL` were also replaced with
placeholders. They were real production identifiers sitting in a tracked file. `DB_NAME` and
`DB_USER` now carry the cPanel `<cpanel_user>_<database>` convention as a comment instead of
the values.

## K-011 · `access.ts` can drift from the server role lists
**Severity:** low · **Status:** **mostly closed on 2026-09-22.**

Three real mismatches were found and fixed. `files` granted `trainer` where
`server/files.php` does not. `dashboard` granted `trainer` and `employee` a page whose
panels mostly 403. `portal` granted every staff role, and the matching server branch had
no role list at all, so an `employee` could pass an arbitrary `?client_id` and read any
client's invoice data that `invoices.php` restricts to three roles. Both ends are now
narrowed and agree.

`canAccess` also **failed open**: a path with no entry in the module map returned `true`,
so a future route added without a map entry would have been reachable by every
authenticated user including `client`. It now fails closed.

The test suite grew from 11 to 21 cases and now asserts the role lists against the
server's, that every module key round-trips through `moduleKeyForPath`, that every role's
landing page is a module it can open, and the `portal` narrowing specifically.

**Still open:** there is no automated check that the TypeScript list and the PHP constant
agree. The tests encode the server's lists by hand, so a change to a PHP role constant
still has to be mirrored by a person.

**The original finding, for the record.**

`src/lib/access.ts` duplicates the per-endpoint role constants by hand. Nothing checks the two
against each other. Drift shows up as a module a user can open but every request inside it
returning 403, or as a hidden module the user could actually use.

`src/lib/access.test.ts` covers the client side only.

## K-018 · The public site is an empty shell to any client that does not run JavaScript
**Severity:** medium · **Status:** **fixed in code 2026-10-16** for the built-in public pages,
not deployed.

**2026-10-16.** The build prerenders the 30 built-in public pages (`docs/ARCHITECTURE.md`
section 2, "Build-time prerender"), each with its own title, description, canonical, Open Graph
and Twitter tags in the served HTML. The build now also fails if any page's canonical or
`og:url` is not its own URL, if its social titles or descriptions differ from its own, or if two
indexable pages share a title, description or canonical; `src/prerender/pages.test.tsx` renders
every page and runs the same checks, and found no gap (all 30 descriptions are page-specific and
50 to 160 characters). Still open: a record that exists only in the CMS is served the shell and
gets its tags only once JavaScript runs, the HTML shows built-in rather than CMS content until
the next build, and the soft 404 below. `public/llms.txt` still describes the site as
client-rendered, which stays true of the live site until this is deployed.

The text below is the original entry.

The site is a client-rendered single-page application with no prerender step. The served
body is `<div id="root"></div>` and nothing else, for every URL. There is no SSR, no
static fallback and no `<noscript>` content.

Googlebot renders JavaScript and will see the pages. Most social scrapers, Bing, and most
LLM crawlers do not, so a shared link or a training crawl sees one generic title and an
empty document.

**Mitigated, not fixed.** Three things reduce the damage:

- The served `index.html` now carries the correct title, description, canonical, Open
  Graph and Twitter Card tags, a `theme-color` and a real 1200x630 `og.png`. Until
  2026-09-22 it carried the **old studio title and description**, so every non-rendering
  client, including every social scraper, saw a stale description of a business that no
  longer describes the site.
- A `<noscript>` block gives a visitor without JavaScript the identity and an email
  address rather than a blank page.
- `public/llms.txt` states the site's content in Markdown for crawlers that read it.

**What remains broken:** the other fourteen routes still serve the home page's metadata
to anything that does not render, because the per-route tags are written by React at
runtime.

**The fix is prerendering the public routes at build time.** That changes the build and
the deploy, so it is recorded here rather than attempted.

Related: `server/.htaccess` rewrites every unknown URL to `index.html` with a 200, so
`/anything-at-all` is a soft 404. The SPA renders a 404 page client-side and that page is
now `noindex`, but the status code is still 200.

## K-021 · The legal pages have no review date and several compliance gaps
**Severity:** medium · **Status:** open. Owner decision, and arguably a solicitor's.

Gaps identified while rewriting the copy, none of which were changed, because the
substance of a legal notice is not an agent's to draft:

1. **No identified data controller and no company registration.** UK GDPR Article
   13(1)(a) requires the controller's identity. `site.studio.registration` is `null`, so

   personal injury from negligence cannot be excluded at all.
6. **No governing law or jurisdiction clause** in the terms.
7. **The cookie claim is unverified.** "Only the cookies needed to make it work" is
   probably true today, since no `document.cookie`, `localStorage` or `sessionStorage`
   use was found on the public surface, but PECR expects cookies to be named individually
   and the deployed site has not been audited.
8. **No processors are named**, which becomes a live gap the moment a mail relay or
   analytics is added.

So that a match is not measurably slower than a miss, `client_access.php` either sends the
neutral answer before any lookup (`fastcgi_finish_request` on PHP-FPM, or
`litespeed_finish_request` on LiteSpeed) or holds every answer to a 1000 ms floor. The tests run
on the PHP built-in server, which has neither function, so only the floor path is tested
(every answer at least 990 ms, spread under 400 ms). The early-finish path is NOT TESTED. On a
host with neither, an SMTP send slower than 1000 ms makes a match slower than a miss. **Before
switching on:** confirm the host's SAPI, or cap the SMTP time below the floor (a shorter SMTP
timeout or a local relay).

## K-102 · Reference sign-in per-IP throttles read `REMOTE_ADDR`
**Severity:** medium if switched on · **Status:** open, a gate before switching on. Real-IP
setup UNVERIFIED.

The per-IP request limit, the per-address-and-IP limit and the failed-redemption limit all
count `REMOTE_ADDR`. Behind Cloudflare, unless the host restores the visitor's address
(mod_remoteip or an equivalent), that is a Cloudflare edge address, and one busy edge could
block many people at once. A valid link is still never blocked, and password sign-in is
unaffected. **Before switching on:** confirm that `REMOTE_ADDR` is the real client IP. A
related residual: three or more IPs together can hold one address at its overall ceiling (15
in 15 minutes), which only delays that person's sign-in link.

## K-103 · The sign-in page logs a 404 in the browser console while reference sign-in is off
**Severity:** low · **Status:** accepted 2026-10-19.

The sign-in page asks `client_access.php?action=status` whether to show the reference form.
While the switch is off (or the file is absent) the answer is 404, by design: every route
answers 404 while off. The page treats it as "off" silently and shows nothing, but the browser
still prints the failed request in its console, and script cannot suppress that. Answering 200
`{enabled:false}` instead would break the "404 on every route while off" rule, so the line
stays. Documented in `src/lib/clientAccess.ts`. Not seen in a browser run (none was done).

## K-104 · Withdrawing consent hides ad slots but cannot unload a loaded script
**Severity:** low · **Status:** open. Built 2026-10-19, switched off, not deployed.

Once a visitor consents, the CMP and AdSense scripts load into the page. If they then withdraw
consent, the slots stop rendering, but a script already running cannot be unloaded; it goes
only on the next page load. Moving to a private route (`/app`, `/login`, `/p`, `/verify`,
`/set-password`) after a third-party script has loaded forces a reload, so no such script runs
inside the CMS, the portal, a proposal or a certificate. NOT TESTED in a browser, and no
network check of accept, reject and withdraw was done (`docs/CONTENT-AND-GROWTH.md` section 3).

## K-105 · An ad slot shifts the article text when it appears after consent

So the slot's own arrival pushes the text below it down, which counts towards layout shift
(CLS). Not measured; no real AdSense unit was loaded. Measure it in the pilot before deciding

## Lessons from closed issues

- Updates must keep what they were not sent: an endpoint that rewrites a field the form never loaded destroys data (K-016 `blog.php` body, K-129 blog status, testimonials, leads and dev meta). Load the stored row (`gk_live_row`) and merge.
- Read `insert_id` straight after the INSERT: `audit()` inserts its own row and changes it (K-029). Create endpoints must be tested for the returned id.
- The Mac and CI databases differ: the Mac runs MariaDB, CI runs MySQL. MariaDB-only SQL (`IF NOT EXISTS` on ALTER or CREATE INDEX) and MySQL 8 reserved words such as `stored` break the schema only in CI (K-040, K-111). Migrations at the foot of `schema.sql` stay commented out until someone runs them.
- Any alternative sign-in path must apply the two-factor rule (K-027 magic links and Google, K-121 Clerk). A new path is not finished until it refuses an account with two-factor on, or proves a second factor.
- Do not trust the stored value in anything that reaches SMTP: validate recipients in the sender (`gk_valid_recipient`), not in each caller (K-120).
- Guarded UPDATEs (`... WHERE used_at IS NULL`, `WHERE status = 'sent'`) inside the transaction stop concurrent clicks minting several sessions or accepting a quote twice (K-027, K-028, K-057).
- Tokens: sessions, reset and magic links are stored as `token_hash()` (first 62 hex characters of SHA-256 in `CHAR(64)`); share tokens are capability links by design (D-029, K-059).
- CSS: an id selector in shared CSS (`#main h1`) outranks class rules on the public site, because both layouts use `id="main"` (K-054). Scope CMS rules with `.gk-app-main`.
- Accessibility traps: `display: none` removes a label from the accessibility tree (use `sr-only`, K-118); Radix `SelectTrigger` needs an `id` with a matching `<Label htmlFor>` (K-088); axe does not test WCAG 1.4.11 (field borders, K-113) or the reduced-opacity text contrast, so measure rendered pixels (K-050, K-115).
- `vite preview` inherits the dev proxy and reaches the live API unless `preview.proxy` is `{}` (K-116). Serve `dist/` with the skill's `serve.mjs`, which answers every `.php` with 404.
- Test harness: `php -S` workers must be started in their own process group and killed as a group, or a later run silently serves an older `server/` (K-089).
- Uploads: the generated `uploads/.htaccess` deny is the only defence against an uploaded script running, and the host needs the PHP `fileinfo` extension or uploads return 503 (K-007).
- First run: with `$SEED_ADMIN_EMAIL` unset an empty `users` table creates no account (K-014). `$MAIL_VERIFY_TLS = true` turns on mail certificate checks and is on in the private config (K-126).
- A paid-invoice flow runs through a draft on purpose (accept quote, draft deposit invoice, Stripe link, webhook): do not make `gk_mark_invoice_paid` refuse drafts (K-131).
- The CI deploy wait must be a `needs` dependency inside one workflow; two workflows triggered by the same push run in parallel (K-035, K-138).
- Several sections were stale against their table row when this file was compacted (K-017, K-069, K-082, K-123); the table row was the later record and was used.
